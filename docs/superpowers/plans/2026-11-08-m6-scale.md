# M6 Scale Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Large notes stay smooth. Viewport culling with unloading of child components and a level of detail for tiny zoom, verified by an extended benchmark against the 1,000 / 5,000 node targets.

**Architecture:**
- **Culling module:** a pure module computes the world viewport (with margin), the level of detail and the visible node IDs, using a spatial grid built once per layout.
- **Renderer:** `DomMapRenderer` (culling on for the view) keeps DOM only for nodes in the viewport plus a margin. Nodes leaving it release their content component; measured sizes and clip state stay. Below a zoom threshold, no node DOM is rendered: all nodes are drawn as one SVG "skeleton" path of rects. Edges and cross-links stay complete.
- **Timing:** culling runs after every layout and, at most once per animation frame, after transform changes.

**Tech Stack:** TypeScript, Obsidian API, Vitest + jsdom, WebdriverIO + wdio-obsidian-service (Obsidian 1.15.0, headless, Xvfb).

**Spec:**
- [docs/mvp.md](../../mvp.md): "Performance (decided)", "Measuring (decided)", "Render ownership", M6.
- Roadmap: [2026-11-08-roadmap-m3-m7.md](2026-11-08-roadmap-m3-m7.md), section M6.

## Global Constraints

- Target: 1,000 nodes pan/zoom smooth at 60 fps; 5,000 nodes still usable.
- Render only nodes in the viewport plus a margin. Edges and cross-connection lines are kept even when one endpoint is off screen.
- Child components are unloaded when a node is culled.
- Render cache and measured size cache by content hash, reused.
- Verified with a benchmark harness on generated notes (frame times logged, compared against a baseline) plus a manual gate. No fps assertions in CI.
- Roadmap targets:
  - longest pan frame at 1,000 nodes ≤ 17 ms;
  - first layout at 5,000 nodes < 1 s (M2: 2.5 s; before M6: 2.9 s);
  - settled at 5,000 nodes < 2 s.

**Measured before M6** (headless, this branch's base `b7669a6`):

| Nodes | First layout | Settled | Longest pan frame |
|---|---|---|---|
| 1,000 | 344 ms | 697 ms | 17 ms |
| 5,000 | 2883 ms | 4031 ms | 33 ms |

### Task 2: Renderer culling and skeleton

**Files:**
- Modify: `src/render/DomMapRenderer.ts`, `styles.css`
- Test: `tests/render/DomMapRenderer.test.ts`

**Interfaces:**
- Constructor option `new DomMapRenderer(parentEl, hooks, { culling: true })`. The default `false` keeps the current behaviour: every node rendered.
- With culling:
  - `setLayout` stores the layout and builds a `SpatialIndex`. It renders edges, toggles (rendered nodes only) and cross-links as before, then calls `updateVisible()`.
  - `setTransform` schedules `updateVisible()` once per animation frame (`canvasEl.win.requestAnimationFrame`).
- `updateVisible(): void` (public; the view calls it after resize). Order of cases:
  1. 0 × 0 canvas: keep the current DOM. On the first layout of a renderer that has never been sized, render all nodes (unit tests and hidden tabs keep working as before M6).
  2. `skeleton` level: no node DOM (everything released). One `path.mind-mapper-skeleton` in the edges SVG holds all node rects (`M x y h w v h h -w Z` per node).
  3. Otherwise: render the nodes in `index.query(worldViewport(...))` and release all others.
- **Clip and selection state** live in the renderer by ID (`setClipped` stores them even for nodes without DOM) and are applied when a node element is created.
- `renderedCount(): number`, for tests and the benchmark.
- **CSS:** `.mind-mapper-skeleton { fill: var(--background-secondary); stroke: var(--background-modifier-border); }`

- [ ] **Step 1: Write the failing tests** (canvas size set via `clientWidth` / `clientHeight`; `requestAnimationFrame` via fake timers or a manual flush):
  - `with culling only nodes in the viewport plus margin have DOM; panning renders new ones and releases left ones`;
  - `edges and cross-links stay complete when nodes are culled`;
  - `below 0.2 zoom the map is a skeleton path, all node content released`;
  - `a culled clipped and selected node gets its classes back when rendered again` (Review Focus 3);
  - `a 0 x 0 canvas renders all nodes on the first layout and keeps the DOM afterwards` (Review Focus 4);
  - `culling a node releases its content through the hook` (Review Focus 2: the view's `NodeContentRenderer` already ignores renders whose owner is gone; this test pins that the hook is called).
