# Roadmap M3–M7

**Spec:** [docs/mvp.md](../../mvp.md). The spec is binding; this roadmap fixes scope, decisions taken ahead of time and the done criteria per milestone. Each milestone gets its own detailed plan (`docs/superpowers/plans/<date>-m<n>-<slug>.md`), written right before it starts, against the code as it is then.

## Process (all milestones)

- Branch `feat/m<n>-<slug>` in `.worktrees/feat-m<n>-<slug>`, from the current `main`.
- Inline execution under TDD; rulings ledgered with their cost.
- Gate before merge, all green:
  1. `npm run check`
  2. `npm run test:e2e` (headless Obsidian under Xvfb)
  3. `npm run screenshots:e2e`, PNGs looked at; every visual bug found gets a geometric E2E assertion
  4. Fresh whole-branch review (most capable model), one fix pass, each fix RED→GREEN
- Then squash-merge into `main` (local only, no push), remove worktree and branch, start the next milestone.
- Rulings and deferred minors of each milestone are kept in the main checkout's `.superpowers/reports/m<n>.md` (survives worktree removal) and collected in the final handover.
- One manual check by the user at the very end (see "Manual check at the end").
- E2E runs against a pinned Obsidian version from M3 on (`1.15.0`), not `latest`.

## M3 — Live companion

**Scope (spec):**
- Live update via `metadataCache` `changed` for the pinned file, using the event's text.
- Debounce 300 ms, generation token, viewport/selection/collapse kept.
- Stable IDs, render and size cache by content hash.
- Collapse/expand with toggle plus commands.
- Selection and double-click jump to source.
- Rename, delete, loading and empty states.

**Decided ahead:**
- **Live update:**
  - Parse from `(file, data, cache)` of the `changed` event, no `cachedRead`.
  - Never re-fits: the viewport is anchored on the selected node, else on the node nearest the view centre (existing `anchoredTransform`).
  - The M2 "re-fit while still fitted" rule stays only for re-measures right after open; a live update clears `fitted`.
- **Render cache:**
  - On a live update a node whose ID changed but whose cache key (`fnv1a(markdown):maxWidth`) matches a node that went away reuses that rendered content element (no re-render).
  - Keyed per update; leftovers are released.
- **Size cache:** pruned to the keys of the current tree after each update (fixes the M2 "grows unbounded" minor).
- **Collapse:**
  - State is an in-memory `Set<id>` per view, kept across live updates; IDs that disappear are dropped.
  - Collapsed subtrees are not laid out or rendered.
  - Toggle: a small circle button on the child-side edge of every node with children. It shows `−` when expanded and the hidden child count when collapsed.
  - Clicking the toggle does not select the node.
- **Collapse all / expand all commands:**
  - Collapse all collapses every node with children except the root (root plus first level stay visible).
  - Expand all clears the set.
  - Both are commands only, no controls button (spec lists them as commands).
- **Selection:**
  - Single click on a node sets `is-selected`; a click on empty canvas clears it.
  - Kept by ID across updates, cleared if the ID disappears.
- **Jump to source (double click):**
  - Uses the node's `line`.
  - Target leaf: the most recently active markdown leaf showing the pinned file. Recency comes from a plugin-level `active-leaf-change` tracker (a `WeakMap<leaf, time>`); this also fixes the M2 "noteLeaf picks first leaf" minor, since link handling uses the same picker.
  - If the note is not open: a vertical split next to the map. Never the map leaf.
  - Cursor: `openFile(file, { active: true, eState: { line } })`; verified in E2E by the editor cursor line.
- **Rename:** a vault `rename` with `oldPath === pinned` updates the pinned path, the tab title (`leaf.updateHeader()`) and saves the layout.
- **Delete:** a vault `delete` of the pinned file shows the empty state "Note was deleted"; a later `create` at the same path reloads.
- **Empty note or frontmatter only:** root only, plus a hint "This note has no content yet".
- **Folded M1/M2 minors:**
  - The loading state can't stick, because the `changed` listener is now permanent.
  - `cachedRead` rejection shows "Could not read note".
  - The render timeout timer is cleared on release.
- **Spike (open topic):** measure the delay between typing in the editor and the `changed` event (headless E2E), record it in the plan.

**Done when, in E2E:**
- Editing the note via the editor updates the map within 1 s, with transform and selection unchanged.
- Collapse toggle, collapse all and expand all work.
- Double click puts the editor cursor on the node's line, in an existing leaf, and in a new split when the note isn't open.
- Rename keeps the map; delete shows the empty state.
- The new screenshots show the collapse toggles and the selection style.

## M4 — Map look

**Scope (spec):**
- The `circle-clockwise` and `circle-counter-clockwise` layouts, plus the remaining linear directions.
- Frontmatter `mind_map_title` and `mind_map_layout` with validation.
- Settings tab; `circle-clockwise` becomes the default.

**Decided ahead:**
- **Layout engine:**
  - One canonical bounding-box tidy tree (main axis = depth, cross axis = stacking), mapped per direction.
  - `top-to-bottom` and `bottom-to-top` swap width and height for the computation.
  - Circle layouts lay out two sides as linear trees:
    - The right side takes the first `ceil(n/2)` first-level children, ordered top to bottom.
    - The left side takes the rest, ordered bottom to top.
    - Each side is centred vertically on the root.
    - `circle-counter-clockwise` mirrors horizontally.
  - `layoutTree(tree, options)` gains `direction: MapDirection`; everything else stays a pure function.
- **Edges and collapse toggles** follow the direction (child-side edge).
- **Frontmatter:**
  - Read from `cache.frontmatter`.
  - `mind_map_title` (string) sets the root label and therefore the root ID; collapse state is lost when the title changes, which is accepted.
  - An invalid value falls back to the default and shows a `Notice` once per note path + key + value per session.
- **Settings:**
  - Fields: default layout (dropdown, default `circle-clockwise`), max node width (160–800, default 320), max node height (120–800, default 240), sibling gap, level gap.
  - Out-of-range input is clamped.
  - A change re-lays out all open maps.
  - Max size reaches CSS through custom properties set on the view element (`--mind-mapper-node-max-width/height`), not hard-coded in `styles.css`.
- **Size cache key:** includes max width and node kind; this fixes the M2 "root styling" minor. The 1 px border is now counted (M2 minor).
- **Contour packing:** only if the screenshots of the fixtures look clearly too sparse; otherwise ruled "not needed" with screenshots as evidence.

**Done when, in E2E:**
- All six layouts produce no overlaps on every fixture.
- Circle clock positions match the spec table for 1, 2, 3, 4 and 6 branches (unit tests on the pure layout).
- Frontmatter overrides work, and an invalid value shows its notice exactly once.
- A settings change re-lays out an open map.
- There is a screenshot per layout.

## M5 — Navigation and polish

**Scope (spec):**
- Cross-connection lines for heading and block links: the collapsed-ancestor rule, safe with culling.
- Back to root and full screen, each with its command.
- File menu entry, ribbon icon, popout windows.

**Decided ahead:**
- **Cross-links:**
  - Source node = the node whose source range contains the link position (`cache.links`).
  - Same-note check via `getFirstLinkpathDest`.
  - The target is resolved with Obsidian's own `resolveSubpath(cache, '#…')` (heading or block). This settles the open topic on heading normalization and duplicates by using Obsidian's resolution, and is verified with a fixture.
  - Target node: a heading maps to its node by line; a block maps to the node whose range contains the block.
  - A hidden endpoint moves to its nearest visible ancestor; a line whose ends meet in one node is not drawn.
  - Computed from the layout, not the DOM, so culling (M6) can't drop them.
  - Drawn as dashed curves in the edges SVG, in the accent colour, below the nodes.
- **Back to root:** control plus command; centres the root at the current zoom and selects it.
- **Full screen:**
  - The leaf container gets a class: `position: fixed; inset: 0`, with a z-index below popovers, modals, notices and menus (below `--layer-popover`), so hover previews and the expand overlay stay visible.
  - Not the browser Fullscreen API.
  - Esc goes through the view's `Scope`, so open modals consume it first.
  - Exit button top right; title chip; controls fade after 2 s idle and reappear on mouse move.
  - Entering fits; exiting restores the previous transform.
  - Jump to source exits first.
  - Command: toggle full screen.
- **File menu and ribbon:**
  - File menu "Open as mind map" for markdown files.
  - Ribbon icon opens the active markdown file (notice if there is none).
- **Popouts:** E2E moves the map into a popout window (`openPopoutLeaf`). It must render, measure, pan and open links; `el.doc`/`el.win` usage is audited.
- **Folded M2 minor:** drop the raw-markdown `title` tooltip on nodes; it competes with page preview.

**Done when, in E2E:**
- Cross-links are drawn for `[[#H]]`, `[[#A#B]]`, `[[#^id]]` and `[[ThisNote#H]]`, follow collapse, and are absent for links to other notes.
- Full screen covers the window, Esc exits, and the transform is restored.
- File menu, ribbon and popout render.
- There is a screenshot in full screen.

## M6 — Scale

**Scope (spec):**
- Viewport culling with child component unloading.
- Benchmark harness, tuned against the 1,000 / 5,000 node target.

**Decided ahead:**
- **Culling:**
  - Render only nodes whose layout rect intersects the viewport plus a margin of one viewport size per side.
  - Culled nodes release their content component and observer; their measured size stays in the size cache.
  - Re-cull on transform change, throttled to one per animation frame.
  - Edges and cross-links stay complete.
- **Measuring with culling:** a node is measured when it first enters the margin. The resulting re-layout is anchored, as already built, so panning into unmeasured areas does not jump the viewport.
- **Benchmark:**
  - Extend `e2e/perf` with per-frame times during scripted pan and zoom, plus time to first layout and to settled.
  - `last-run.json` is compared against `baseline.json`, with a printed diff.
  - No fps assertions (spec), but E2E asserts the DOM node count stays bounded with culling.
- **Targets (headless numbers as evidence, the manual check confirms):**
  - At 1,000 nodes, a longest pan frame ≤ 17 ms, matching the M2 baseline.
  - At 5,000 nodes, first layout under 1 s (M2: 2.5 s), settled under 2 s.
- **Tuning** only where profiles show cost; each change is measured before and after and recorded in the plan.

**Done when:**
- Culling holds in E2E: the DOM node count is bounded, edges are complete, and the overlay, links and collapse still work.
- The benchmark runs, and the baseline is updated with the improved numbers.

## M7 — Release prep (local only)

**Scope:** everything for a community submission that can be done locally. No push, no GitHub release, no submission.

- **Name check:**
  - Look for `mind-mapper` / "Mind Mapper" clashes in the official `community-plugins.json`.
  - Check the current submission rules (naming, description, manifest) on docs.obsidian.md; this settles the open topic.
  - Findings with links go in the M7 report.
- **`minAppVersion`:**
  - The oldest Obsidian version that has every API used, from the `@since` tags in `obsidian.d.ts`.
  - Verified by running the E2E suite against that version.
  - `versions.json` is updated.
- **Files:**
  - Check LICENSE, `manifest.json` (description rules) and the release assets (`main.js`, `manifest.json`, `styles.css`) built by `npm run release`.
  - Folded M0 minors: version script message, zip requirement, error notice on a failed open.
- **README:**
  - Screenshots, generated headlessly from a demo note.
  - Commands with suggested hotkeys.
  - Settings, frontmatter keys, known limits.

**Done when:** `npm run release` produces the assets, the README is complete, and the name-check result is documented.

## Manual check at the end (user)

Things headless Obsidian cannot show:
- Trackpad pinch and two-finger pan.
- How hover previews feel.
- A popout window on a real desktop.
- Full screen together with OS window chrome.
- Theme and font switching.
- How smooth a large note feels.
- Typing in a note with the map open beside it.

The checklist will be in the final handover.
